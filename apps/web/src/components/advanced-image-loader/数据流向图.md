一句话总结：

加载阶段：
URL → fetch → Blob

快速解码/裁剪阶段：
Blob → createImageBitmap → ImageBitmap

兼容降级阶段：
URL → HTMLImageElement → Canvas.drawImage

统一输出阶段：
ImageBitmap / HTMLImageElement
        ↓
      Canvas
        ↓
toBlob / toDataURL
        ↓
      图片 URL

缓存阶段：
图片 URL
   ↓
canvasCache
   ↓
下次直接 <img src="缓存URL">

还有一个你面试时最好单独记住的核心：

```text
Blob
    = 编码后的图片二进制数据

ImageBitmap
    = 解码后的位图资源
    = 不是 URL

Canvas
    = 最终绘制结果

canvas.toBlob()
    = 把 Canvas 像素重新编码成图片 Blob

URL.createObjectURL(blob)
    = Blob → blob: URL

canvas.toDataURL()
    = Canvas → Base64 Data URL
```

所以最核心的数据转换关系就是：

```text
URL
 ↓
Blob              ← 编码数据
 ↓ decode
ImageBitmap       ← 解码后的位图
 ↓ render
Canvas            ← 最终像素
 ↓ encode
Blob              ← 裁剪结果的编码数据
 ↓
Object URL        ← 最终可作为 img.src 的地址
```

这个 **`encode → decode → render → encode`** 链条，你理解清楚之后，这整套图片 Pipeline 基本就不会乱了。
