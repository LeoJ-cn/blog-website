Browser 验证发现了一个真实交互问题：右键菜单能出现，但点击菜单按钮时浏览器会把正文选区折叠，导致核心类拿不到原 Range，因此标注没有创建。这是旧实现的事件时序缺陷；我会在右键打开时缓存 Range，点击“添加标注”时使用缓存副本，然后重新验证。




已使用 浏览器编辑了多个文件运行了命令



进一步检查确认 Browser 的右键动作会先折叠 Selection（真实浏览器在不同平台也可能出现这种差异）。仅在 contextmenu 时读取选区仍不够稳。我会改为持续缓存最后一个合法非空 Range，并且只有右键坐标仍落在该 Range 的可视矩形内时才使用它，避免误用旧选区。




已使用 浏览器编辑了多个文件运行了命令



根因已定位：标注核心成功修改正文 DOM 后，页面回调更新“标注数量/提示语”，Vue 随即重新协调同一正文子树，把手工插入的高亮节点覆盖掉了。正文必须明确交给标注引擎独占管理；我会给文章容器加 v-once，让 Vue 只负责初始渲染，不再重写内部 DOM。




已使用 浏览器编辑了多个文件读取文件



诊断结果表明 Range 和 offset 都有效，问题落在菜单按钮依赖 document 委托点击：浏览器自动化触发按钮时，委托分支没有稳定进入。菜单本身是独立浮层，我会把“添加”处理器直接绑定到菜单容器，并让 document 只负责点击外部时关闭菜单；这也能减少全局事件判断。
