# AI + Figma 企业级页面自动化开发实战课程 V3.0

核心主线：Figma MCP → Code Connect → Vue3 → Playwright → AI 自动修复

## 第一阶段：让 AI 真正理解 Figma 和项目

### 第 01 章｜企业级 AI 页面生成架构与开发环境

建议 40 分钟｜基础必学

1.1 AI Coding 工作原理

- Codex / Claude Code 如何读取文件、搜索代码、调用命令和修改工程。
- Agent、MCP、Skills、AGENTS.md、Tools 的区别及关系。
- 为什么截图 + Prompt 无法可靠生成生产级页面。
- AI 页面生成的完整任务链路。

1.2 搭建开发环境

- 准备 Vue3 + Vite + TypeScript 项目。
- 复用已有企业组件库或搭建最小模拟组件库。
- 配置 Codex / Claude Code。
- 配置 Git 工作区，隔离 AI 修改。

1.3 工程目录设计

- 设计解析产物目录。
- 组件映射清单目录。
- AI 开发规范与 Skills。
- Playwright 测试目录。
- 视觉差异报告目录。

1.4 企业开发中的 AI 工作模式

- 设计读取 Agent。
- 页面生成 Agent。
- 代码规范检查。
- 视觉与交互验证。
- 自动修复及质量门禁。

本章产出： 可运行的基础项目、标准目录结构、AI 工作流程架构图。

### 第 02 章｜Figma MCP 接入与 AI 读取设计稿

建议 60 分钟｜核心章节

2.1 Figma MCP 原理

- 什么是 MCP Server。
- Codex 如何连接 Figma MCP。
- Remote MCP 与 Desktop MCP 的区别。
- Figma API、Figma MCP、Figma 插件 API 的区别。

2.2 实操接入

- 配置 Figma MCP。
- Figma 账号授权。
- 获取 Frame / Node URL。
- 验证 Agent 是否真正读取到设计信息。

2.3 重点掌握 MCP 工具

- `get_design_context`：读取设计上下文。
- `get_screenshot`：获取设计截图。
- `get_metadata`：读取节点结构信息。
- `get_variable_defs`：获取设计变量。
- `get_code_connect_map`：获取代码组件映射。

2.4 解析 Figma 结构化数据

- Frame / Group / Component / Instance。
- Auto Layout 与 CSS Flex / Grid 的关系。
- 宽高、间距、字体、颜色、圆角等参数。
- 设计素材、图片与 SVG。
- 响应式约束与信息缺失的处理。

2.5 AI 生成设计解析报告

- 自动分析页面布局。
- 提取设计 Token。
- 提取组件清单。
- 形成 Design Spec。
- 标记无法读取或存在歧义的信息。

2.6 处理真实工程问题

- Figma 页面很大，如何分节点读取？
- MCP 返回的信息不完整怎么办？
- MCP 产生的代码不是 Vue 怎么办？
- 如何避免设计信息过多导致上下文膨胀？

本章产出： Figma 连接成功、节点数据读取演示、设计解析 JSON、Design Spec 和可复用 Prompt。

### 第 03 章｜Code Connect：Figma 组件与企业 Vue3 组件库映射

建议 75 分钟｜最高优先级

这章直接对应面试官的核心追问：如何保证 AI 使用的是自己的组件库？

3.1 企业组件库知识体系

- 企业组件库如何组织。
- Vue3 组件 Props、Emits、Slots。
- TypeScript 类型如何为 AI 提供准确上下文。
- Storybook 如何提供组件用法和交互案例。
- 如何扫描内部组件库，提取组件元数据。

3.2 Code Connect 工作原理

- Figma 组件与真实代码组件的关联机制。
- Code Connect UI 和 CLI 模板方案。
- Vue3 项目应该如何建立代码示例。
- 组件属性及变体如何映射到 Vue Props。
- 如何让 MCP 返回可复用的真实组件信息。

3.3 实操组件映射

以以下组件为例：

| Figma          | Vue3 内部组件 |
| -------------- | --------- |
| Primary Button | AppButton |
| Form Input     | AppInput  |
| Data Table     | AppTable  |
| Dialog         | AppDialog |
| Select         | AppSelect |

3.4 AI 如何选择正确组件

- 按 Figma 组件标识匹配。
- 按设计语义和组件能力匹配。
- 如何读取真实组件 API。
- 避免 AI 编造不存在的 Props。
- 组件库不存在对应组件时怎么处理。

3.5 企业组件注册表

- 生成 Component Registry。
- 组件的导入路径和 API Schema。
- 组件映射的版本管理。
- 如何处理 Figma 设计系统与代码组件库不同步。

本章产出： 内部组件元数据清单、Code Connect 映射、组件匹配示例和缺失组件报告。

## 第二阶段：控制 AI 生成代码与交互

### 第 04 章｜AGENTS.md + Skills：让 AI 按公司规范开发

建议 60 分钟｜最高优先级

4.1 AI Context Engineering

- AI 为什么会忽略组件库？
- 如何有效提供项目上下文。
- 全局规则、项目规则、任务规则。
- 如何减少无关代码和文档干扰。

4.2 AGENTS.md 实战

- 规定项目技术栈和目录。
- 规定组件库来源。
- 规定 Design Token 使用。
- 禁止擅自新增 UI 依赖。
- 约束修改文件范围。
- 规范生成后的验证流程。

4.3 Skills 实战

创建三个可复用技能：

- `figma-to-vue`：读取设计并生成页面。
- `component-guard`：检查内部组件使用规范。
- `visual-verify`：视觉测试与修复。

4.4 如何实现真正的组件约束

- Prompt 软约束的局限。
- ESLint 自定义规则。
- Vue 模板 AST 检查。
- 依赖白名单。
- 检查原生标签绕过公司组件的问题。
- CI 强制校验。

4.5 AI 不遵守规则怎么办？

- 自动提取违规项。
- 生成修复任务。
- 定向修改，不影响无关模块。
- 未通过规则检查不允许交付。

本章产出： AGENTS.md、3 个示例 Skills、ESLint/AST 组件规则及可执行检查命令。

### 第 05 章｜AI 自动生成高保真 Vue3 页面

建议 70 分钟｜核心实操

5.1 AI 页面生成的正确顺序

- 先读取设计信息。
- 再分析现有项目和组件库。
- 再生成页面结构。
- 再配置组件属性和 Design Tokens。
- 最后补充交互行为。

5.2 从 Figma 到 Vue3

- Figma Auto Layout → Flex / Grid。
- Figma Variables → CSS Variables。
- Figma Component → Vue3 Component。
- Figma 图片 / SVG → 项目资源。
- 如何处理字体、间距和布局约束。

5.3 生成真实企业页面

以用户管理页面为例：

- 查询区域。
- 数据表格。
- 分页。
- 新建 / 编辑弹窗。
- 表单输入。
- Loading、Empty、Error 状态。

5.4 减少 AI 生成偏差

- 如何避免硬编码样式。
- 如何避免大量绝对定位。
- 如何避免私自实现 Button / Table。
- 如何避免生成不存在的组件参数。
- 如何拆成多次小任务，提高生成稳定性。

5.5 AI 代码生成验收

- 检查组件导入和实际使用。
- 检查 TypeScript 类型。
- 检查布局和 Design Tokens。
- 检查修改范围和代码可维护性。

本章产出： 一个基于设计规范和内部组件库生成的 Vue3 管理页面。

### 第 06 章｜AI 读取交互、生成业务逻辑与自动化测试

建议 60 分钟｜核心章节

6.1 页面交互的信息来源

- Figma Prototype。
- Figma Variants。
- PRD / 业务需求。
- Storybook / 组件文档。
- OpenAPI / 后端接口。
- 项目已有交互和状态管理代码。

6.2 怎么提取 Figma Prototype 信息

- MCP 可读取范围及限制。
- Figma REST API 的原型数据。
- Figma Plugin API 的 Reactions。
- 点击、跳转、弹窗、状态切换。
- 缺失信息如何标记和补齐。

6.3 让 AI 生成 Interaction Contract

将交互统一整理成：

`事件 → 条件 → 动作 → 状态 → 结果 → 来源`

6.4 AI 生成 Vue3 交互

- 弹窗打开和关闭。
- 表单双向绑定与校验。
- Loading 和重复提交。
- API 请求与异常处理。
- 列表刷新、路由跳转。
- Vue3 响应式状态及 Pinia。

6.5 AI 自动生成交互测试

- 从交互契约生成测试。
- 如何 Mock API。
- 如何覆盖成功、失败和边界条件。
- 如何验证交互契约覆盖率。

本章产出： 交互契约文件、Vue3 业务逻辑、自动化交互测试用例。

## 第三阶段：视觉验收、自动修复与企业交付

### 第 07 章｜Playwright：AI 自动化视觉还原验证

建议 75 分钟｜最高优先级

7.1 视觉验证体系

- Figma 设计基准图。
- 浏览器实际渲染图。
- 图像差异图。
- 视觉回归和设计一致性测试的区别。

7.2 Playwright 实操

- 安装配置。
- 启动 Vue3 页面。
- 设置视口、DPR 和浏览器。
- 处理字体、资源、动画和 Mock 数据。
- 自动生成浏览器截图。

7.3 图像差异分析

- pixelmatch。
- PNG 像素比较。
- 差异率计算。
- 差异图生成。
- 对大面积空白或背景的误差控制。

7.4 DOM 与 CSS 精确验证

- BoundingBox。
- ComputedStyle。
- 关键元素宽高和位置。
- 字体、颜色、间距和圆角。
- 布局错位、文字换行和溢出检查。

7.5 多状态和多视口验证

- Desktop / Tablet / Mobile。
- Hover / Focus / Disabled。
- Loading / Empty / Error。
- Modal / Dropdown / Tooltip。

7.6 如何定义验收标准

- 什么叫视觉还原率。
- 为什么不能绝对承诺 100%。
- 如何制定视觉误差阈值。
- 如何输出可审计的视觉验证报告。

本章产出： Playwright 视觉测试、Figma 对比截图、Diff 图、差异率和 DOM/CSS 差异报告。

### 第 08 章｜AI 自动分析差异与迭代修复

建议 60 分钟｜核心章节

8.1 构建自动修复工作流

`执行测试 → 收集失败 → 分析原因 → 修改代码 → 重新测试`

8.2 AI 如何理解错误

- 读取 Playwright 报告。
- 分析视觉 Diff。
- 读取 DOM / CSS 差异。
- 分析 ESLint 和 TypeScript 错误。
- 区分设计问题、组件问题和代码问题。

8.3 让 AI 定向修复

- 修复错误的组件 Props。
- 修复布局约束。
- 修复 Design Tokens。
- 修复表单交互。
- 修复类型与组件规则违规。

8.4 避免 AI 越改越乱

- 限制自动修复次数。
- Git diff 审查。
- 修改文件白名单。
- 自动测试防止回归。
- 无法修复时输出待确认报告。

8.5 修复效果量化

- 比较每轮视觉差异。
- 统计测试通过率。
- 记录组件使用情况。
- 生成最终修复报告。

本章产出： 自动检查和修复流程、每轮差异报告、自动修复演示。

### 第 09 章｜AI 生成代码的 CI/CD 质量门禁

建议 45 分钟｜架构面试加分

9.1 AI 代码质量治理

- 代码规范与类型正确性。
- 组件规范检查。
- 自动化功能测试。
- 视觉回归测试。
- 避免 AI 改动无关业务。

9.2 CI 自动验收

- ESLint。
- Typecheck。
- Vitest。
- Playwright。
- 视觉 Diff。
- 内部组件使用规范。

9.3 企业级架构设计

- Figma / 组件库 / 项目版本管理。
- 设计与代码同步机制。
- 自动生成的设计规范如何维护。
- 视觉基准图更新审批。
- 失败报告如何交给 AI Agent 修复。

9.4 研发效率与成本

- 减少重复读取设计数据。
- 控制上下文大小和 Token 成本。
- 哪些任务适合并行 Agent。
- 哪些环节必须人工审核。
- 如何衡量交付效率和质量。

本章产出： CI 验收流程、组件规范门禁、质量报告模板。

## 五、后续每章统一输出规范

为了确保不是只有理论，每章都按照以下七个部分展开：

1. 核心原理：从高级前端/架构师视角讲清楚技术机制。
2. 实操步骤：具体安装、配置、执行和查看结果的方法。
3. 关键代码：给出可以在真实项目中改造使用的代码。
4. 完整 Codex Prompt：直接复制即可操作，明确前置条件和输出目标。
5. 验证和排错：怎么证明操作成功，常见失败怎么解决。
6. 面试题及标准答案：基础题、进阶题、架构深挖题。
7. 本章验收清单：确保真正掌握，再继续下一章。

对于暂时没有真实 Figma 或企业组件库的情况，先使用模拟项目和示例组件进行实战；之后再替换成真实项目，不会把模拟结果描述成真实项目的验证结果。
