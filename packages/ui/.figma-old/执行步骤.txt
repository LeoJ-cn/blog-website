好，我们采用逐步执行、逐步验证的方式。每一步确认成功后，再进入下一步，避免最后发现数据缺失却不知道哪个环节出了问题。

整个流程分为 6 步：

| 步骤 | 操作                               | 验证目标                     |
| -- | -------------------------------- | ------------------------ |
| 1  | 检查配置和运行环境                        | `source.yaml`、Token、依赖正常 |
| 2  | 创建 `fetch.sh`                    | 自动读取 YAML 并执行 REST       |
| 3  | 获取 `raw/index.json`              | 文件、Pages、Frames 正确       |
| 4  | 获取 `target.json`、`related.json`  | 目标及关联状态数据完整              |
| 5  | 提取 `interactions.yaml`、`assets/` | 交互与素材可用                  |
| 6  | Codex 调用 MCP，生成 `context.md`     | 补充设计语义和组件映射              |

这次先执行第 1 步。

## 下一步：先自动生成 `interactions.yaml`

我们暂时只做交互提取，不急着下载关联节点。这样可以先确认数据转换正确。

### 5.1 在 `.figma/fetch.sh` 中添加一个函数

把下面函数放在脚本现有函数区域：

```
fetch_interactions() {
  local input="$RAW_DIR/target.json"
  local output="$ROOT/.figma/interactions.yaml"

  [[ -f "$input" ]] || {
    echo "缺少 target.json，请先执行 target"
    return 1
  }

  jq --arg id "$NODE_ID" '
    [
      .nodes[$id].document
      | .. | objects
      | select(has("id") and has("type") and (.interactions? | type == "array"))
      | . as $node
      | .interactions[]
      | . as $interaction
      | ($interaction.actions // [])[]
      | {
          source_node: $node.id,
          source_name: $node.name,
          trigger: $interaction.trigger.type,
          action: .type,
          navigation: (.navigation // null),
          target_node: (.destinationId // null),
          transition: (.transition // null),
          evidence: "figma-rest"
        }
    ]
  ' "$input" | yq -P -p=json > "$output"

  echo "已生成 $output"
}
```

这里保留真实的 Figma 节点 ID、事件类型、目标节点和动画信息，不推断业务逻辑。

### 5.2 添加命令分支

在 `fetch.sh` 原有的 `case` 命令分支中加入：

```
interactions)
  fetch_interactions
  ;;
```

保持原来的 `check`、`index`、`target` 分支不变。
